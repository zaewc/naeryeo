# 제품 구현 진행

2026-10-04 사용자 지시로 일반 사용자 Now Bar 표시 검증을 후속 제품 개발의 선행 조건에서 해제했다.
표시가 성공했다고 기록하는 것은 아니다. 기존 실기기 결과와 Samsung 문의는 그대로 유지한다.
우선 지원 지역은 광주 버스다. 공통 도메인 → 테스트 운행 → 공식 API → 백그라운드 추적 순으로 구현한다.

## 실제 데이터 연결

[광주버스정보 공식 API](https://www.data.go.kr/data/15157923/openapi.do)는 정류소, 노선,
노선별 경유 정류소, 도착정보, 버스위치를 제공한다. 인증키가 필요하며 개발 활용신청은 자동승인으로 안내된다.
확인한 페이지의 개발계정 신청 가능 트래픽은 100이므로 실시간 polling 정책은 실제 승인 한도 확인 후 설정해야 한다.
API 키를 앱 번들·EXPO_PUBLIC 변수·저장소에 넣지 않는다. 서버에서 보관하고 정규화된 데이터만 앱에 전달한다.
현재 인증키·실제 API 응답이 없어 실제 광주 차량 추적은 검증되지 않았다.

## 공통 진행 계산

정류장 ID와 노선 내 순번을 구분한다. 순환 노선에서 같은 정류장을 재방문할 수 있다.
남은 정거장은 순번 차이가 아닌 탑승 이후 목적지까지 실제 경유 정류장 개수로 계산한다.
차량 노선 불일치·존재하지 않는 순번·역방향 목적지·미래 관측을 거부한다.
오래된 차량 관측은 stale로 구분하고 ETA를 실시간 예측으로 노출하지 않는다.

## 실제 데이터 연결

- 사용자 발급 키로 공식 API의 노선 목록, 순환01A 정류장 50개, 실제 차량 위치 호출 성공.
- 서버는 `.env`의 인증키를 읽고 노선/정류장/차량 위치를 정규화한다. `.env`는 Git 제외.
- 앱은 노선 검색 → 차량 번호 선택 → 현재 위치 이후 목적지 선택 → 하차 알림 시작/위치 갱신/종료 화면을 제공한다.
- 테스트 운행과 Now Bar 진단은 별도 화면으로 분리한다.
- 아직 자동 백그라운드 갱신, 외부 서버 배포, 갤럭시 설치 후 전체 이동 검증은 완료되지 않았다.

## 네이티브 자동 갱신

- 사용자 시작 동작으로 Android `dataSync` 포그라운드 서비스를 실행한다. 차량 정보는 네이티브에서 15초마다 조회하며 JS는 화면에 보이는 동안 저장 상태만 읽는다.
- 동일 차량 ID, 노선, 정류장 순서 및 역행을 검증한다. 위치가 끊기거나 오래되면 확인 중으로 표시하고 경고를 중복 발생시키지 않는다.
- 다음 정류장과 도착 시 알림을 갱신한다. 도착 시 서비스를 종료하고 완료 알림/저장 상태는 사용자가 종료할 때까지 남긴다. 실행은 최대 2시간이며 Android 서비스 제한 시간 콜백도 처리한다.
- 서버는 캐시 관측 경과 시간 `ageMs`를 반환한다. 앱/서비스는 기기 시각으로 변환하여 서버와 기기 시계가 달라도 정상 관측을 거부하지 않는다.
- API 36 에뮬레이터에서 **실제 순환01A 차량**으로 검증: 일반 알림 권한 허용 → 서창농협벽진지점 하차 선택 → 앱을 홈으로 이동 → 관측 갱신 → 실제 차량 정류장 진행에 따른 도착 알림 → 서비스 자동 종료 → 앱 재진입 시 완료 상태 복원 → 완료 버튼으로 알림/저장 상태 제거.
- 갤럭시는 재연결할 수 없어 이 버전의 삼성 Now Bar 표시 검증은 미실시. 외부 서버 배포와 기기 재설치도 아직 완료되지 않았다.
